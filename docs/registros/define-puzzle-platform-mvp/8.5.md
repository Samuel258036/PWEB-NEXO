## Comparação com as quatro especificações

| Especificação | Comportamentos conferidos e evidência |
| --- | --- |
| [Entrada](../../../nexo-para-recomecar/openspec/changes/define-puzzle-platform-mvp/specs/terminal-entry/spec.md) | A primeira visita exibe uma pergunta e um campo. Busca por nome, entrada discreta na autoria, retorno ao início, conteúdo literal e foco passaram no Chromium. Os endereços diretos de autoria aguardam a sessão e retomam o destino após identificação. [Interface e rede](../../../e2e/accessibility.spec.js) · [Acesso direto](../../../e2e/author-entry.spec.js) |
| [Identidade](../../../nexo-para-recomecar/openspec/changes/define-puzzle-platform-mvp/specs/user-identity/spec.md) | Cadastro confirmado, equivalência de nomes, senha literal, concorrência de cadastro, origem e CSRF foram comparados aos testes da API. O ensaio em HTTPS verificou o cookie seguro. O logout rejeitado preserva a sessão e a edição, apresenta falha e permite repetir. Somente a saída confirmada mostra o encerramento. [Autenticação](../../../api/test/auth.test.js) · [Proteção de requisições](../../../api/test/security.test.js) · [Logout](../../../e2e/author-entry.spec.js) |
| [Autoria](../../../nexo-para-recomecar/openspec/changes/define-puzzle-platform-mvp/specs/puzzle-authoring/spec.md) | Os testes conferem rascunho e IDs, salvamento, nomes exclusivos, autorização, publicação e congelamento da estrutura, edição permitida, conflitos, bloqueio da resposta e exclusão integral. Em atualização com versão vigente, a API conserva a resposta bloqueada e permite salvar o enunciado. O teste de acesso direto comprovou o `404` para um rascunho de outra conta. [Testes da API](../../../api/test/author.test.js) · [Percurso completo](../../../e2e/nexo.spec.js) |
| [Progressão](../../../nexo-para-recomecar/openspec/changes/define-puzzle-platform-mvp/specs/individual-progression/spec.md) | A API separa o progresso, só entrega o conteúdo liberado e valida apenas o texto. Os testes conferem erro sem perda, avanço único, revelação e manutenção de dicas, conclusão retomável e indisponibilidade após exclusão. O ensaio operacional preservou sessão, etapa, dica e versão após reinício e restauração em cópia. [Progressão](../../../api/test/play.test.js) · [Operação](../../../api/test/operations.test.js) |

A revisão técnica reproduziu desvios nas rotas diretas e no encerramento da sessão. O navegador agora preserva o destino após a identificação, autoriza a abertura pela API e só limpa a edição após confirmar a saída. O teste também verifica que a lista permanece aberta após reidentificar a mesma conta e após criar um rascunho enquanto outro ainda carrega.

## Execução integrada

| Comando | Resultado |
| --- | --- |
| `npm run lint` | Passou. |
| `npm test` | 54 testes da API passaram, incluindo o ensaio operacional. |
| `node --test web/src/*.test.js` | 9 testes da interface passaram. |
| `npm run test:e2e -- --workers=1` | O build de produção passou e os 4 cenários Playwright passaram. |

Ambiente de verificação com Windows, Node 24.11.1, Playwright 1.65.1, Chromium e Express/SQLite reais. Os testes Playwright usam TLS direto em loopback e o perfil móvel é emulado a 320 px.

## Pendências para o piloto

Aplicar o roteiro com participantes e observar o teclado virtual em aparelhos físicos. A eventual publicação externa ainda depende de provedor, domínio, HTTPS e volume persistente. O arquivamento do OpenSpec segue a revisão da implementação. [Roteiro do piloto](../../piloto.md) · [Guia de operação](../../operacao.md)
