# 3.3. Identificar, cadastrar e entrar

## O que foi entregue

A API oferece quatro rotas em `/api/auth`: `GET /session` informa a conta da sessão atual e fornece um token CSRF; `POST /identify` diz se o nome normalizado já está cadastrado; `POST /register` cria a conta somente depois de receber `confirmedNew: true`; e `POST /login` confere o nome e a senha.

O cadastro trata dois pedidos simultâneos com o mesmo nome: a restrição UNIQUE do banco permite apenas uma conta e o outro pedido recebe `409 NAME_TAKEN`. Cadastro e login bem-sucedidos renovam o ID da sessão. As respostas incluem apenas o ID e o nome de exibição, sem senha ou hash. A validação de CSRF e de origem, o limite do corpo e o controle de tentativas ficam para a tarefa 3.4.

## Como conferir

Na raiz do projeto, execute:

```powershell
node --test api/test/config.test.js api/test/passwords.test.js api/test/session-store.test.js api/test/auth.test.js
```

Os 16 testes devem passar. Os testes de autenticação usam servidor HTTP local, banco temporário e migração 0001 por meio de `node:sqlite`. A integração com `better-sqlite3` não foi verificada porque o driver nativo aguarda o Windows SDK; o ESLint também não está instalado e a suíte completa não foi executada.
