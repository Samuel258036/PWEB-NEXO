# 3.2. Guardar sessões no SQLite

## O que foi entregue

O servidor agora guarda sessões no SQLite, renova sua expiração, remove registros vencidos e configura o cookie `nexo.sid`. O segredo `SESSION_SECRET` precisa ser definido e mantido igual entre reinícios para que as sessões continuem válidas. Se a aplicação estiver atrás de um proxy HTTPS, configure `TRUST_PROXY_HOPS` com a quantidade real de proxies confiáveis; o valor `1` do exemplo é apenas ilustrativo.

Ainda não há rotas reais de cadastro, login ou logout: elas serão feitas na tarefa 3.3. Os testes usam rotas temporárias criadas só para conferir a persistência após reiniciar o servidor e a troca do ID da sessão.

## Como conferir

Na raiz do projeto, execute:

```powershell
node --test api/test/config.test.js api/test/passwords.test.js api/test/session-store.test.js
```

Os 12 testes devem passar. Nesta sessão, o banco temporário foi exercitado com `node:sqlite`; a integração com o `better-sqlite3` da aplicação, o lint e a suíte completa ainda precisam ser verificados quando as dependências puderem ser instaladas.
